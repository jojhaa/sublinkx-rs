# 订阅导出内容

在订阅管理的新增或编辑表单中选择“导出内容”：

- **节点＋规则**：保留原有完整模板导出，包括 DNS、网站分流与规则集。
- **仅节点**：保留节点和策略组，包括手动选择、自动选择、国家分组、负载均衡、故障转移及风险/住宅分组；不附带 DNS、网站分流和规则集。

国家与风险分组仍遵守现有数据资格、数量阈值和客户端能力；此开关不强制生成没有合格节点的分组。Clash/Mihomo 的“仅节点”设置 `mode: rule` 并仅保留一条 `MATCH,节点选择` 兜底规则，让进入核心的流量跟随所选策略组。没有“节点选择”的模板使用现有主组（如“代理选择”），无组时才退回 DIRECT；不重命名现有组。客户端若覆写运行模式或规则，仍以客户端最终生效配置为准。DNS 继续依赖客户端提供；其他格式的仅节点行为不变。

Clash/Mihomo YAML 保留 `proxies`、`proxy-providers` 和 `proxy-groups`，加上规则模式及唯一 MATCH；移除 DNS、网站规则和 `rule-providers`。sing-box 保留 `outbounds`；文本配置保留节点、WireGuard 参数与策略节。URI、SIP008 等本来不含规则的格式保持原样。自定义模板也遵守订阅选择，模板原文不修改。MATCH 语义参考 [Mihomo 官方规则文档](https://wiki.metacubex.one/config/rules/#match)。兜底修复已于2026-09-11随v0.2.28部署生产，12条有效订阅的两种YAML输出通过兜底规则和核心校验；客户端更新原订阅后生效，实际联网仍待用户设备验收。

设置保存在订阅上，原链接、复制、二维码与门户导出使用同一设置。订阅 Token 不变，客户端更新订阅后获取新内容；旧客户端已经缓存的配置不会被服务端主动清除。

## API 与升级

`POST /api/v1/subscriptions` 和 `PUT /api/v1/subscriptions/{id}` 新增可选布尔字段 `include_rules`。列表、详情与门户解锁响应返回该设置。

- 新增时省略：默认 `false`（仅节点，保留策略组）。
- 编辑时省略：保留原值，兼容旧客户端的续期、开关和其他操作。
- SQLite 未发布的新迁移 `0023_subscription_include_rules.sql`；MySQL/PostgreSQL 幂等建列，默认 `0`，历史订阅首次升级后使用“仅节点”。旧链接与 Token 不变，客户端更新订阅才获取新内容。
- 手动选择“节点＋规则”后会持久保存，不在每次启动时强制覆盖。此前本地实验使用旧版 0023 的临时测试库不能直接复用，需另建隔离测试库；生产 PostgreSQL 已于 v0.2.27 完成增量建列。
- 跨数据库迁移清单包含此字段，导出缓存键区分两种模式。

2026-09-11 已部署生产 v0.2.27，升级前完成数据库和配置备份并保留旧镜像。15条历史订阅默认仅节点，链接与Token指纹不变；12条有效订阅通过Clash/Mihomo内容及核心加载检查，另2条无符合导出条件的节点而被拒绝。风险审核设置保持开启，未绕过安全过滤。SQLite本地升级与PostgreSQL生产增量升级已验证；MySQL实际迁移、完整数据库恢复演练及真实用户客户端联网尚未验收。应用回滚可使用保留的0.2.26镜像与配置，数据库恢复需另行确认，不能直接覆盖上线后的数据。

## 验证

后端常规测试覆盖默认值、SQLite 历史数据升级、仓库读写、Token 保留、导出裁剪、国家负载/故障转移组保留与缓存隔离。`scripts/check-subscription-content.ps1` 仅允许连接本地隔离测试实例；浏览器检查脚本位于 `frontend/scripts/check-subscription-content-browser.js` 和 `check-subscription-content-edit.js`，测试账户仅供隔离开发库使用。
